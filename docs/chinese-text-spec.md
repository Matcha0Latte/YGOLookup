# 简体中文 OCG 效果文本规范

本文档是中文 Effect Parser 的规范依据。中文是 source language，英文 enum 是 machine protocol。

依据来源：

- 游戏王 OCG 规则（第九期以后的文本格式，即 PSCT 的中文对应形态）
- <https://ocg-rule.readthedocs.io/zh-cn/latest/c02/基本用语.html>
- <https://ocg-rulebook.readthedocs.io/zh-cn/latest/c02/卡片的效果.html>
- 数据源实测（ygocdb `cards.zip`，14,342 条）

---

## 1. 文本分层

一张卡的完整文本按此顺序组织：

```text
[素材行]            「火焰操纵者」＋「传说的剑豪 正树」    仅融合/同步/连接等
[灵摆效果]          pdesc                                 仅灵摆怪兽
[global restriction] 「这个卡名的①②的效果1回合各能使用1次。」
[效果 ①]             ①：……
[效果 ②]             ②：……
[效果 ③]             ③：……
```

### 1.1 效果编号

第九期以后用带圈数字 **① ② ③ ④** 标记效果，紧跟**全角冒号** `：`。

实测：14,342 条中 9,756 条含 `①`，6,488 条含 `②`，1,864 条含 `③`。

### 1.2 global restriction

位于所有编号效果**之前**的独立句子，描述跨效果的次数限制，**不属于任何一个 ①/②**。

常见形态：

```text
这个卡名的①②的效果1回合各能使用1次。
这个卡名的①③的效果1回合各能使用1次。
「杀人蛇」的效果1回合只能使用1次。
这个卡名的效果1回合只能使用1次。
```

判据：不含编号标记、含「1回合各能使用1次」/「1回合只能使用1次」等次数限制措辞、位于第一个编号标记之前。

实测：含「这个卡名」的卡有 5,145 条。

### 1.3 灵摆

`pdesc` 存灵摆效果文本，`desc` 存怪兽效果文本，二者在数据源里已经分离，**不需要**自己切 `【灵摆效果】`。

实测：`pdesc` 非空 374 条；`desc` 中不含 `【灵摆效果】` / `【怪兽效果】` 标记（0 条）。

注意：灵摆卡的 `pdesc` 第一个「①：」之前可能还有没有编号的发动条件句，例如
「自己场上没有怪兽存在的场合才能把这张卡发动。」——它属于整个灵摆区域卡的发动条件，
应单独成 unit。

### 1.4 素材行

```text
「火焰操纵者」＋「传说的剑豪 正树」
衍生物2只
2只4星怪兽
```

素材行**不是效果**，必须单独标记 `unit_kind = MATERIAL` 且不产出任何 Clause。

### 1.5 子选项

编号效果内部可用 `●` 列举互斥子选项（实测 1,148 条含 `●`）：

```text
①：从以下效果选择1个或者两方才能把这张卡发动。
●对方怪兽的攻击宣言时，以那1只攻击怪兽为对象才能发动。那只攻击怪兽变成守备表示。
●以自己场上1只表侧表示怪兽为对象才能发动。……
```

## 2. 单个效果的内部结构

第九期以后的文本，**效果处理写在「发动」之后**。一个编号效果的内部顺序固定为：

```text
①： [次数限制] [发动条件] [cost] [以…为对象] 发动 。 [效果处理] 。
                         ↑
                    「发动」是分界线
```

### 2.1 「发动」锚点

| 措辞 | 含义 |
| --- | --- |
| `才能发动` | 选发效果（旧译，简中官方较少用） |
| `可以发动` | 选发效果（**简中官方现用措辞**） |
| `发动` （裸） | 必发效果 |
| `必定发动` | 必发效果（强调） |
| `把这张卡发动` | 卡本身的发动（魔法/陷阱/灵摆设置） |

⚠️ 简中官方对选发效果采用「~~可以发动」而非「~~才能发动」。实测含「才能发动」的仍有 8,907 条（历史文本），两种都必须支持。

### 2.2 CONDITION vs COST（关键）

**「发动」之前的内容要再分 CONDITION 和 COST，判据不是「才能发动」本身，而是片段里有没有可支付的动作。**

| role | 判据 | 例子 |
| --- | --- | --- |
| `CONDITION` | 状态 / 时点描述，无动作动词 | 自己场上没有怪兽存在的场合 / 这张卡在墓地存在的场合 / 对方回合 / 自己主要阶段 / 这张卡召唤成功时 |
| `COST` | 含可支付动作（把…除外 / 丢弃 / 解放 / 送去墓地 / 支付 / 取除 / 回到…） | 把墓地的1只光属性怪兽除外 / 把这张卡从手卡丢弃 / 支付1000基本分 / 把这张卡2个超量素材取除 |
| `TARGET` | 含「以…为对象」 | 以对方场上1只怪兽为对象 |
| `RESOLUTION` | 「发动」之后的部分 | 那只怪兽破坏 |
| `RESTRICTION` | 次数限制 / 不可做某事 | 这个卡名的效果1回合只能使用1次 / 这张卡不能通常召唤 |
| `UNKNOWN` | 无法确定 | — |

依据规则原文：「在第九期以后的情报文本中，cost 会清楚的写在『发动』之前」。

⚠️ **反例**：「自己场上没有怪兽存在的场合才能发动」—— 「才能发动」前面只有状态描述，**是 CONDITION 不是 COST**。

实测：含「为对象」的卡 4,134 条。

### 2.3 取对象

第九期以后记述「以…为对象」= 取对象。只写「选」= 不取对象（旧文本写「选择」）。

### 3.4 数值比较

统一结构化表达，禁止 `max_level` / `min_atk` 这类专用字段：

```json
{ "op": "<=", "value": 4 }
```

| 中文 | 结构化 |
| --- | --- |
| 4星以下 / 4星以下 | `{ "op": "<=", "value": 4 }` |
| 等级4 | `{ "op": "==", "value": 4 }` |
| 5星以上 | `{ "op": ">=", "value": 5 }` |
| 攻击力1500以下 | `{ "op": "<=", "value": 1500 }` |
| 攻击力1500以上 | `{ "op": ">=", "value": 1500 }` |
| 守备力0 | `{ "op": "==", "value": 0 }` |

## 4. 已知陷阱（parser 必须处理）

| 陷阱 | 说明 |
| --- | --- |
| **换行是 `\r\n`** | 实测 8,453 条含 `\r\n`，切分前必须归一化 |
| **引号内卡名污染** | 「青眼白**龙**」/「**暗**黑界」里的种族属性词不得被判为种族/属性。所有 `「…」` 片段必须先脱敏 |
| **数字歧义** | 「4星以下」的 4 是等级不是数量；「1只」的 1 是数量。数量必须绑定量词（只/张/个） |
| **否定** | 「不能通常召唤」是 RESTRICTION，不是 `NORMAL_SUMMON` |
| **OR 条件** | 「手卡或墓地」先按第一个分支记录，同时把全部候选记入 `modifiers` |
| **额外卡组 vs 卡组** | 见 3.2 |
| **锚点优先** | 「发动」锚点只在**第一个**出现处切分，避免「发动无效」这类后半句误切 |

## 5. 第一版不处理

按需求，第一版只做检索用语义解析，**不实现**：

- 连锁 / 咒文速度
- 伤害步骤
- 时点错过（「时」vs「场合」的差异）
- 永续效果（replacement / lingering）
- 完整召唤手续
- 完整裁定逻辑

第一版只回答：

```text
这张卡【在什么条件下】付出了【什么 cost】对【什么对象】做了【什么动作】，从【哪里】到【哪里】，有【什么限制】
```
